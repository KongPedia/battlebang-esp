# `examples/`

Example command payloads, provisioning config, and OTA manifest payloads.

- `config.turret_5.json` shows first USB provisioning shape. Replace Wi-Fi, MQTT host, turret id, pose, calibration, and OTA desired build before use.
- `ota-manifest.example.json` shows the public release manifest structure generated by `scripts/turret_fleet/make_release_manifest.py`.
- `pattern.lane_sweep.json`, `pattern.two_point_bounce.json`, and
  `pattern.telegraph_column.json` are the BTB-726 player-readable boss attack
  examples. Command Center publishes them per turret on
  `battlebang/turrets/{turret_id}/command`. The example points use `y` for left/right and negative
  `z=-0.6` so `turret_2` pitches downward with margin inside the configured safe
  yaw/pitch envelope. `lane_sweep` starts fire for each sweep leg, caps that fire window by
  `fire_ms`, cuts early at the yaw endpoint, waits 500 ms, then starts the
  return leg; the point patterns
  move first, dwell, then fire.

Runtime pattern preset config is intentionally stored outside `examples/` under
`src/turret_fleet/pattern_presets/` to avoid mixing command examples with NVS
configuration payloads. Publish `src/turret_fleet/pattern_presets/turret_2.json`
with `./bin/turret fleet-mqtt turret_2 config --profile-file src/turret_fleet/profiles/turret_2.json --patterns-file ...`;
high-level pattern commands can then omit `--point` and use the configured NVS
preset.

Examples must not contain real Wi-Fi passwords, MQTT passwords, or private broker hostnames.
